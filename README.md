# ドミニオン

デッキ構築型カードゲーム「ドミニオン」をブラウザで遊べるようにしたものです。スマホの横画面向けに作っていて、CPU との対戦と、友人とのオンライン対戦ができます。

**遊ぶ:** https://123yoshidandy.github.io/dominion/

## できること

- **カード**（すべて第2版。拡張「収穫祭」と「ギルド」は2024年の合本「収穫祭＆ギルド」）
  - 基本セットの王国カード26種
  - 拡張「陰謀」の王国カード26種（複数の種類を持つカード、選択肢から選ぶ効果など）
  - 拡張「海辺」の王国カード27種（持続カード、島マット・原住民の村マット、前哨地の追加のターンなど）
  - 拡張「繁栄」の王国カード25種と白金貨・植民地（勝利点トークン、効果のある財宝、コストの軽減など）
  - 拡張「異郷」の王国カード26種（獲得したとき・廃棄したとき・捨て札にしたときの効果など）
  - 拡張「収穫祭＆ギルド」の王国カード26種と褒賞6種（財源、超過支払い、災いカード、渡し守の山など）
  - ゲームごとに、開始画面でチェックしたセットからランダムに10種を使う。繁栄のカードが多いほど白金貨と植民地を使いやすい
- **CPU 対戦**：2〜4人。人間とCPUを席ごとに選べる（同じ端末で人間どうしが交代で遊ぶこともできる）
- **オンライン対戦**：部屋を作って招待URLを送り、2〜4人（CPUも入れられる）で遊ぶ。接続が切れても同じ席に戻れる
- **操作**：カードはタップでプレイ・購入、長押し（PCでは右クリック）で説明を表示。購入フェーズに入ると手札の財宝をすべてプレイし、財源は「財源を使う」で1つずつ使う。購入回数を使い切ると自動でターンを終える
- **設定**：手札の同じカードを重ねて表示する、など。設定と名前はブラウザに保存する

## 遊び方

### CPU 対戦
1. 開始画面で人数・名前・CPUかどうか・使うカードを選び、「ゲーム開始」を押す

### オンライン対戦
1. 開始画面で「オンラインで遊ぶ」を押し、名前を入れて「部屋を作る」を押す
2. 「招待URLを共有」で友人にURLを送る（友人は開いて名前を入れ、「参加する」を押す。部屋番号（数字5桁）でも参加できる）
3. 部屋を作った人が、CPUの追加や使うカードを選んで「ゲーム開始」を押す
4. ゲームが終わったら、部屋を作った人が「部屋に戻る」で同じメンバーと続けて遊べる

## 開発

必要なもの：Node.js 22 以上、Python 3（画面を手元で配信するため）

```bash
npm install

# 画面を手元で配信して http://localhost:8080 を開く
python3 -m http.server -d public 8080

# テスト
npm test
```

### オンライン対戦を手元で試す

AWS を使わずに、同じ処理のテスト用サーバーを手元で動かせます。画面を `localhost` で開くと、自動でこのサーバーにつながります。

```bash
npm run dev:server   # ws://localhost:8787
```

URLに `?server=wss://...` を付けると、接続先のサーバーを変えられます。

## 構成

```
public/            画面（GitHub Pages でそのまま公開する）
  js/
    game.js          ゲームの進行（DOMに依存しない。サーバーでも使う）
    player.js card.js card-types.js
    card-data.js     基本セットのカードと、全カードのまとめ
    card-data-*.js   拡張ごとのカード（card-helpers.js は効果の共通部品）
    card-art*.js     カードのイラスト（SVG。拡張ごとにファイルを分けている）
    cpu-player.js    CPUの戦略
    game-view.js     プレイヤーごとに見える状態（他の人の手札などを含まない）
    random.js        シード付きの乱数（同じ操作の記録から同じゲームを再現する）
    game-controller.js   ローカル対戦のコントローラー
    online-controller.js オンライン対戦のコントローラー
    ui-*.js          画面の描画と操作
server/            オンライン対戦のサーバー
  src/room-service.js  部屋の処理（作成・参加・操作の受け付け・CPUの進行）
  src/handler.js       Lambda の入口
  src/dynamo-store.js  DynamoDB への保存
  dev-server.js        手元で試すためのテスト用サーバー
  template.yaml        AWS SAM のテンプレート
test/              テスト（Vitest）
```

### オンライン対戦のしくみ

- サーバーがゲームを進め、各プレイヤーにはその人から見える状態だけを送る（相手の手札や山札の並びは送らない）
- 部屋には参加者・乱数のシード・操作の記録だけを保存し、操作を受けるたびに記録からゲームを再現する
- CPU はサーバーで動かし、1手ずつ届ける

## サーバー（AWS）

API Gateway（WebSocket）・Lambda・DynamoDB を AWS SAM で作ります（東京リージョン、スタック名 `dominion-online`）。

- 部屋は最後の操作から2日、ログは7日で自動的に消える
- 想定外のアクセスに備えて、受け付けるリクエストの数に上限を設けている
- 料金の通知（AWS Budgets）を任意で作れる。アカウント全体の今月の料金が上限（既定は1ドル）を超えたとき・超えそうなときにメールで知らせる

### デプロイ

AWS SAM CLI と AWS CLI が必要です。プロフィールは環境変数で渡します。変更内容を表示し、確認してから反映します。

```bash
AWS_PROFILE=<プロフィール名> npm run deploy:server -- \
  --parameter-overrides "BudgetEmail=<通知先> BudgetEmail2=<2つ目の通知先（任意）>"
```

料金の通知のメールアドレスは、デプロイのたびに渡してください（渡さないと通知が消えます）。デプロイ後に出力される `WebSocketUrl` を、`public/js/online-config.js` の `DEPLOYED_SERVER_URL` に書きます。

画面（`public/`）は main ブランチに push すると GitHub Pages に反映されます。
